## 1. 问题与主张范围

问：常用的 grounding 核查器，会不会把"比证据说得更肯定"的句子判为有依据？
论文是**元评测**，只主张受控最小对上的行为。不主张真实 RAG 输出里这类错误有多常见，不主张发现了"认识侵蚀"，不主张所有核查器或所有领域都如此。

## 2. 试点给了什么，没给什么

- 试点 300 篇文档、329 条编辑**全部排除**在确认性数据之外，只用于定设计。下面的门槛都参考了试点，是看过试点之后定的，但先于确认性数据。
- 沿用的教训：0.5 阈值掩盖分级扣分；AUROC 条款有歧义，且对 weaken 也是 1.000；标签集在看过分数后才定；report 类 70/81 被摘要支持。
- 输入格式：试点的 MiniCheck 用成对编码，官方是 `eos_token.join([doc, claim])` + 400 token 分块取最大。在试点数据上按官方格式复跑（`runs/minicheck_format_v1`，分句用 SciFact 而非 nltk）：RoBERTa 有效 modal 接受率 0.95→0.92，hedge 0.93→0.90，翻转 54/56→50/56；DeBERTa 0.82→0.82，0.97→0.93，43/56→42/56。试点格式曾截断 156（RoBERTa）/96（DeBERTa）对输入。**正式运行用官方格式。**

## 3. 假设

主假设 6 条（3 组 × 2 个模型）。**每条单侧检验，水平 0.05/6（Bonferroni）**，按模型分别成立或不成立。

| 编号 | 内容 | 成立标准 | 试点参考（官方格式） |
|---|---|---|---|
| H1-R / H1-D | 摘要前提下，MiniCheck-RoBERTa / DeBERTa 接受有效膨胀 | modal **和** hedge 的接受率，单侧 Clopper–Pearson 下界都 > 0.70 | R：0.92、0.90；D：0.82、0.93 |
| H2-R / H2-D | 加上下文使 modal 膨胀更容易被接受 | 接受率（摘要）−接受率（仅原句）的 bootstrap 下界 > 0.20 | R 拒绝 56/78 → 翻转 50；D 56/78 → 42 |
| H3-DS / H3-QM | 写明强度规则能减少前沿评审放行 modal | 接受率（通用）−接受率（强度）的下界 > 0.10，且护栏：identity 和 weaken 的接受率下降都 ≤ 0.05（点估计） | DS 0.73→0.45；QM 0.68→0.06 |

H2 用全部有效 modal 行，不只用"原句被拒"的行，避免按结果选样。
**次要（只报估计和区间，不作成立/不成立判断）：** causal、scope、some→all；评测库流程；推理模式评审；DeBERTa-large NLI；Qwen3-4B。
**删去：** report 类不进入本研究；nli-deberta-v3-base 因试点 identity 0.06 不用。

## 4. 数据与抽样

- SciFact 语料，sha256 与试点一致（`11c621288d41…`），减去试点 300 篇，剩 4,883 篇、40,667 个合格句（8–60 词）。
- 每篇文档在整个研究里只用一句、一种编辑。分配顺序从稀到多：hedge（471 篇可用）→ scope（655）→ causal（656）→ modal（1,247）。some→all（408）**[已定]** 只取 60 条作次要。以上是 v1 规则的计数，规则改成 v2 后重新计数。
- 句序按 `SHA-256("P10-CONFIRM-v1:doc_id:sent_idx")` 排。按此顺序进入标注，**不看任何分数**。

## 5. 编辑规则 v2（冻结前完成，只在试点数据上调试）

1. `animal model` 先于 `animal` 匹配；删范围后若留下悬空名词或缺主语则跳过（试点 10/44 broken）。
2. modal：跳过从句和目的句里的 may/might、"may have + 过去分词"、"unclear/not well understood … may"等自相矛盾的上下文（试点 16/103 broken）。
3. some→all：跳过列举和 "some of the most"。
4. weaken：不对以连词、OBJECTIVE/METHODS 标签开头或已含 possible/hoped/postulated 的句子使用；negate：跳过含多个从句且否定后自相矛盾的模式（试点各 7/40 broken）。
5. 每条都加回归测试。v2 定稿后在试点 300 句上重跑规则，人工看一遍，**不跑模型**。

## 6. 标注（先于任何分数）

- 单人标注，不做第二人，**不报告一致性**；写入局限。工作簿不含模型输出。标注人若知道假设，也写入局限。
- Q1 编辑完好；Q2 只看两句是否更强；Q3 摘要是否支持编辑后的说法；Q4（scope）读者按泛指还是存在性理解。
- 定义补充（针对试点的 27/42 contested）：**从相关变为因果一律记 Q2=yes**，除非原句本身已是因果；句子别扭属于 Q1，不属于 Q2。broken 行停止作答。
- **主分析集（有效）= Q1∈{ok, minor} 且 Q2=yes 且 Q3=no。** scope 另要求 Q4=generic。原句前提的分析不看 Q3，但 H2 两侧都用同一批有效行。
- 敏感性集（只报告）：contested 计入；Q1=minor 剔除；全部编辑。
- 标注完成后冻结文件并记录 sha256，**之后才允许运行模型**。之后发现的错误只能作为偏离记录，同时报告改前改后的结果。

## 8. 指标与判定规则

- **接受率**：被判为有依据的比例。**各配置只用自己的规则：**
  - MiniCheck、NLI：官方的 P(supported) > 0.5。
  - LLM 评审：P(Yes) ≥ 0.5。
  - LlamaIndex、Phoenix：库自身的二值判定。
  - DeepEval：库默认 `threshold = 0.5`（4.3.4 `faithfulness.py` 第 75 行已核对）。
  - RAGAS、TruLens：在检索过的文件里**没有找到默认通过线**，不设阈值，改报"编辑的分数低于 identity 的比例"，并附满分规则的接受率。
- **强度特异性** = 膨胀的下降 − weaken 的下降（相对 identity，同一句配对），用来区分"察觉变强"和"察觉改动"。
- **不用 AUROC 作任何判定。**
- **可解读门槛（逐个配置，事先写明）：** identity 接受率 ≥ 0.90，且 negate 下降 ≥ 0.70。不达标的配置单列，不解读其膨胀结果。按试点数字，DeepEval 默认（negate 0.43–0.48）和 LlamaIndex+DeepSeek（0.67）会不达标；它们对否定的漏判照实报告。**若 MiniCheck 任一不达标，该模型的 H1、H2 判为不成立。**
- 区间：H1 用 Clopper–Pearson；配对差用按文档 bootstrap 10,000 次（种子 20261124），描述性结果给 95% 区间。若 bootstrap 退化（全 0 或全 1），改用精确区间。
- API 失败：同一请求最多重试 6 次；仍失败记缺失，不计为接受或拒绝。缺失 > 2% 的配置不解读。确认性集的 10% 重跑一次，报告前后判定一致率。

## 9. 结果怎么读（事先写好）

- H1 两个模型都成立：标题结论限于"MiniCheck 在文档级核查中放行 modal 和 hedge 膨胀"。只有一个成立：结论只写那一个模型。
- H2 成立但填充对照也同样升高：写"长度本身就能造成"，不写"内容造成"。
- H3 成立：结论是"可由提示改善"，并报告对 weaken 和 identity 的代价。护栏不过：写"提示让评审更严"，不写"更敏感"。
- H1 不成立：照实报告，不换阈值、不换子集、不改成次要指标补救。
- 次要结果一律写"描述性"。scope 的"泛指"是单人判断，措辞从严。
